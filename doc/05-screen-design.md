# 勤怠管理Webシステム 画面設計 v0.1

要件定義書 v1.2 / ユースケース定義 v0.1 / ユビキタス言語 v0.1 を踏まえた画面構成・遷移・各画面仕様の定義。

> 対応デバイス: **PC のみ**（スマホ非対応）

## 1. 画面一覧・URL 構造

App Router のルートグループ機能で **認証境界** を分離する。

```
app/
├── (public)/                        ← 未認証エリア（middleware: 認証不要）
│   ├── login/                       → /login
│   └── password/
│       └── initial/                 → /password/initial
├── (member)/                        ← メンバー認証境界（role: member）
│   └── member/
│       └── dashboard/               → /member/dashboard
└── (admin)/                         ← 管理者認証境界（role: admin のみ）
    └── admin/
        ├── dashboard/               → /admin/dashboard
        └── users/                   → /admin/users
```

| # | 画面名 | URL | アクセス可能ロール | 関連 UC |
| --- | --- | --- | --- | --- |
| S-01 | ログイン | `/login` | 未認証 | UC-01 |
| S-02 | 初回パスワード変更 | `/password/initial` | `mustChangePassword === true` | UC-03 |
| S-03 | メンバーダッシュボード | `/member/dashboard` | member | UC-02 / UC-04 / UC-05 / UC-06 / UC-07 / UC-15 |
| S-04 | 管理者ダッシュボード | `/admin/dashboard` | admin | UC-02 / UC-04〜10 / UC-15 |
| S-05 | ユーザー管理 | `/admin/users` | admin | UC-11 / UC-12 / UC-13 / UC-14 |

> 管理者は自身も打刻するため、`/admin/dashboard` の上部に **自分用打刻パネル** を組み込む（メンバーダッシュボードと同じ機能）。

### S-01 ログイン

- **目的**: 社員 ID とパスワードで認証
- **アクター**: 未認証ユーザー
- **関連 UC**: UC-01

#### レイアウト

```
+--------------------------------------------------------+
|                                                        |
|                  勤怠管理（プレゼンス）                  |
|                                                        |
|       +-------------------------------------------+    |
|       |  ログイン                                  |    |

|       |  社員 ID                                   |    |
|       |  [_______________________________]        |    |
|       |                                           |    |
|       |  パスワード                                |    |
|       |  [_______________________________]        |    |
|       |                                           |    |
|       |              [   ログイン   ]              |    |
|       |                                           |    |
|       |  [認証エラー時はここに Alert を表示]        |    |
|       +-------------------------------------------+    |
|                                                        |
+--------------------------------------------------------+
```

#### 画面要素

| 要素 | コンポーネント | 説明 |
| --- | --- | --- |
| 社員 ID 入力 | `Input` | 必須・空文字不可 |
| パスワード入力 | `Input type="password"` | 必須 |
| ログインボタン | `Button` | submit |
| エラー表示 | `Alert variant="destructive"` | 認証失敗・無効化済アカウント時 |

#### バリデーション（Zod）

- `employeeId`: `z.string().min(1)`
- `password`: `z.string().min(1)`

#### ステータス遷移

- 認証成功 + `mustChangePassword === true` → `/password/initial`
- 認証成功 + `mustChangePassword === false` + role=member → `/member/dashboard`
- 認証成功 + role=admin → `/admin/dashboard`
- 認証失敗 → エラー表示
- 無効化済アカウント → エラー表示（UC-01 代替フロー 3c）

- 該当日にレコードが無い user → ステータス `休み (Off)` で表示（行は出す）
- 離業中の場合: ステータス列に `[離業中]`、勤務形態列は出勤打刻時の値を維持

## 5. モーダル仕様

### M-01 打刻情報修正モーダル

- **呼び出し元**: S-03 の「修正」ボタン（自分） / S-04 の各行「修正」ボタン（任意）
- **関連 UC**: UC-07（自分） / UC-09（管理者）

#### レイアウト

```
+-----------------------------------------------------------+
| 打刻情報を修正 - 田中太郎  2026-05-07                     |
+-----------------------------------------------------------+
| 現在ステータス: [ 勤務中 ]                                |
|                                                           |
| 出勤打刻                                                  |
|   時刻: [ 09 : 30 ]   勤務形態: [ 在宅勤務 ▾ ]             |
|                                                           |
| 退勤打刻                                                  |
|   時刻: [ -- : -- ]   勤務形態: [ -      ▾ ]             |
|                                                           |
| 離業期間                                       [ + 追加 ]  |
| ─────────────────────────────────────                    |
| #1  開始: [ 12 : 00 ]  終了: [ 13 : 00 ]   [削除]         |
| ─────────────────────────────────────                    |
|                                                           |
|                          [ キャンセル ] [ 保存 ]          |
+-----------------------------------------------------------+
```

#### 画面要素

| 要素 | コンポーネント | 説明 |
| --- | --- | --- |
| 時刻入力 | `Input type="time"` | HH:mm |
| 勤務形態選択 | `Select` | clockIn は出社/在宅/直行、clockOut は通常/直帰 |
| 離業期間追加ボタン | `Button` | 行を増やす |
| 離業削除ボタン | `Button variant="ghost"` | 該当行を削除 |
| 保存ボタン | `Button` | submit |
| キャンセルボタン | `Button variant="outline"` | モーダルを閉じる |

#### バリデーション

- 出勤時刻 ≤ 退勤時刻
- 各離業期間: 出勤時刻 ≤ 開始時刻 ≤ 終了時刻 ≤ 退勤時刻
- 離業期間同士の重複禁止
- 適用後のステータス整合性（L4 / 3.2 不変条件）が保たれること
- **手動追加した離業期間は開始時刻・終了時刻の両方が必須**（クローズ済みの期間のみ追加可。L16 と整合）
- アクティブな離業期間の削除はステータス整合性違反としてエラー（UC-07 代替フロー 2c）

#### アクティブな離業期間（`endedAt === null`）の扱い

- M-01 内では **read-only で表示**（編集・削除はできない）
- アクティブな離業期間をクローズするには、モーダルを閉じてダッシュボードの **`業務復帰` ボタン**（UC-15 / `markBack()`）を使う
- これは Domain L16 の「アクティブな期間の編集・削除は `markBack()` 経由」の制約に合わせるため

## 7. 共通の挙動

| 項目 | 方針 |
| --- | --- |
| エラー表示 | フォーム内: `FormMessage` で field 単位 / 全体: `Alert` または `Toast` |
| 成功通知 | `Toast`（"打刻しました"・"保存しました" 等） |
| ローディング | ボタンに `disabled` + spinner（連打防止） |
| 楽観的 UI 更新 | TanStack Query の `mutate` で即時反映 → 失敗時にロールバック |
| セッション切れ | API 401 を検知 → `/login` へリダイレクト |

## 8. 残課題

- **リアルタイム更新方式**: S-04 の一覧を自動更新するか（ポーリング N 秒 / SSE / 手動リロード）
- **パスワードポリシー**: 桁数・文字種ルールの確定（M-02 / S-02 のバリデーションに直結）
- **`EmployeeId` 形式**: 桁数・文字種ルールの確定（M-02 のバリデーション）
- **無効化済みアカウントの再有効化 UI**: M-03 に再有効化ボタンを置くか（残課題 Q3 と連動）
- **タイムゾーン表示**: 全時刻を JST 固定で表示する旨の注記をどこに置くか
- **UI ノベリ・ブランディング**: ロゴ・配色トーン（shadcn デフォルトでスタートする想定）
